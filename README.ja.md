> Sieve Crowd は、表形式データにおける個人の特定リスクを抑え、安全に共有するためのテーブルデータ加工エンジンです。k-匿名性および l-多様性の原理に基づき、属性の丸め加工（一般化）と一部レコードの除外（抑制）を決定論的に行います。

完全ローカル実行・外部依存ゼロ・決定論的（100%再現可能）な、テーブルデータの匿名化・再識別を無効化する数理的変換エンジンです。[Sieve-Core](https://github.com/neguseatama/sieve-core) の設計思想をテーブルデータドメインへ拡張したプロジェクトです。

## 💡 コンセプトと開発思想

個人データを手元で安全に管理していても、それらの情報を含む表データを外部へ提供・公開しなければならないことがあります。あるいは漏洩のリスクを抱えます。一方で、統計的に見れば、年齢・郵便番号・性別といった複数の属性が組み合わさることで、個人の特定につながるリスクは常に存在します。

例えば、あるデータセット（600人規模）を例に取ると、そのリスク構造が明確になります。

- **処理前**: 600人のうち574人（96%）が、年齢・郵便番号・性別の組み合わせにおいて「自分と同じ条件の人が他にいない（＝孤立した1人）」状態となっており、外部から容易に特定されてしまいます。
- **変換の仕組み**: 本エンジンは、この孤立したデータを放置せず、類似するレコード同士をグループ化（丸めや一般化）することで、全員が安全な集団に紛れ込むよう構造を変換します。
- **処理後**: その結果、全員が「自分を含めて5人以上のグループ（4人の似た者）」に属するようになり、特定を試みても正解を当てる確率は最大でも20%（1/5）に抑えられます。

Sieve Crowd は、確率的な推測やブラックボックスなAIに頼らず、厳密な数学的モデル（k-anonymity / l-diversity）に基づいて、表データを「誰も目立たない安全な状態」へと決定論的に変換します。

- **決定論的アプローチ**: 同一の入力と設定からは、常に全く同じ出力が得られます。実行環境や時刻、乱数に依存しません。
- **結果は約束ではなく測定**: 処理後のデータが目標とする安全基準を満たしているかを事後的に数え直します。基準に届かなければ、理由はレシートに示され、表は出力されません。
- **説明可能性**: 匿名化のためのデータ処理を記したレシートを出力し、何が行われたかを完全に追跡できます。

## 🧩 Sieve シリーズ

Sieve は、決定的・ゼロ依存・完全ローカルという共通の設計原則を共有するエンジン群です。各エンジンが 1 つのリスクの観測または排除を担い、相互に接続します:

| パッケージ | 役割 | 接続 |
| :--- | :--- | :--- |

| [sieve-lens](https://github.com/neguseatama/sieve-lens) | 文書内の不可視コンテンツ・隠しプロンプトを観測 | — |
| [sieve-scope](https://github.com/neguseatama/sieve-scope) | 構造的に類似したコードペアを検出 | — |
| [sieve-referee](https://github.com/neguseatama/sieve-referee) | 言い換え・流用されたテキストペアを検出 | — |

| [sieve-crowd](https://github.com/neguseatama/sieve-crowd) | 表形式データにおける再識別リスクの観測と匿名化（k-匿名性） | — |

## 🔥 主な特徴

- **k-anonymity と l-diversity の適用**
  各レコードに少なくとも k−1 人の「似た者」が存在するように属性を一般化し、さらに機微情報の多様性を保証します。
- **ゼロ依存・完全ローカル**
  Python標準ライブラリのみで実装。データがパソコンの外に出ることは一切ありません（アカウント不要、オフライン、アップロードなし）。
- **最小限の一般化と抑制（Suppression）**
  データを必要以上に丸めず、解像度をできるだけ保ったままグループ化を行います。それでも他のデータとグループを作れない孤立したレコードは、無理に歪めず安全に除外（抑制）します。
- **列の役割の提案（hint packs）**
  `inspect` / `plan` が、組み込みの `jp-basic` パック（v0.5.1 から既定オン、`--no-builtin-hints` で除外）で、列への役割の提案と値の形の検査を行います。氏名・フリガナ・住所・生年月日・メール・電話番号・マイナンバー・カード番号・郵便番号（v0.7.3 からハイフン形 `123-4567`、v0.7.4 からは電話番号 `090-1234-5678` とカード番号 `4242-4242-4242-4242` のハイフン形も）を、列名と値の両面で照らし、直接識別子（`id`）と準識別子（`qi`）の候補を出します。v0.8.2 からは、性別らしい列名（`qi`・階層なしの `category`）と病名らしい列名（`sensitive`）を列名だけで照合します。パックは直接識別子（`id`）・準識別子（`qi`）・機微列（`sensitive`）の候補を出します。提案は列名か値の合図がある列にだけ付き、宣言との食い違いは `role_mismatch` として観測します。ヒントは匿名化には一切触れません。
- **事前プラン（plan）**
  `sieve-crowd plan` が、探索の前に正確な探索空間の大きさ（格子ノード数）、除外の上限、段階0のリスク・プロファイル、警告（届かない k / l、上限不足、孤立レコードの多さ）、そして v0.6.0 からは keep 列と準識別子の導出関係（keep 列が準識別子をほぼ決めていないか、その逆も含め双方向）を報告します。チューニングを「実行後」ではなく「実行前」に。
- **表を今のまま監査（audit）**
  `sieve-crowd audit` が、現在の表を整数だけで観測します。同値類とサイズ別の行数、どの準識別子列がグルーピングを担っているか、そして `--subject` があれば行の背後にいる人。行の上では k に届いても、人の上では k 人に届かない同値類を、判定ではなく件数として数えます。
- **レシート内の診断（diagnostics）**
  レコードが除外されたとき、レシートが理由を説明します。群れの大きさ、「k 未満」か「多様性不足」かの別、さらにどの準識別子を1段階粗くすれば救われるかの列ごとのヒント。すべて集計値のみで、セルの値は一切出ません。
- **数値列のカスタム区間（bins）**
  「0-19, 20-39, 40-64, 65以上」のような不均一な区分（法定年齢階級、所得階層など）を、境界値のリストとして直接指定できます。
- **欠損値の方針（missing_value_policy）**
  準識別子が空のレコードの扱いを設定できます。`star`（既定）は他の値と同じく `*` に一般化し、`suppress` は検索の前にそのレコードを除きます（同じ除外予算に算入。予算を超えると `missing_exceeds_budget` で拒否）。埋め値（placeholder）は意図的に提供しません。埋めた値は、欠損パターンそのものを識別子に変えてしまいます。
- **レシートによる記録**
  処理の事実（適用ルール、抑制件数、測定値）を記した機械可読なレシートを出力します（レシートに個人情報は含まれません）。
- **対応フォーマット**
  CSV・JSON・XML（UTF-8）をサポート。外部ライブラリに依存しないため、現行まではExcelを対象外としています。

## 💻 クイックスタート

### 1. 構造の検査

ファイルを読み込み、各列の役割（氏名、準識別子、機微情報など）の目安を提案する設定ファイルを出力します。

```bash
sieve-crowd inspect people.csv --config-out config.json
```

### 2. 設定の確認・編集

生成された `config.json` を編集し、各列の役割を定義します。

### 3. 事前プランの確認（任意）

実行の前に、探索の規模・除外の上限・段階0のリスク構造を確認できます。探索は行われず、何も書き込まれません:

```bash
sieve-crowd plan people.csv -c config.json
```

### 4. 匿名化の実行

```bash
sieve-crowd run people.csv -c config.json -o people_safe.csv --report-json receipt.json
```

入力・出力の例:

```
people.csv                                       people_safe.csv   （行はシャッフル済み）
```

## 🔍 表を今のまま監査する（audit、v0.7.0）

`sieve-crowd audit` は、表が **今どう見えているか** を観測します。一般化もせず、除外もせず、拒否もせず、そして判定もしません。`plan` が実行の見積り、`run` が表の変換だとすれば、`audit` は数えるだけです。報告はすべて整数で、割合は千分率の切り捨て（整数の除算、浮動小数点なし）。そのため同じ表は、どの環境でもバイト同一の出力になります。

```bash
sieve-crowd audit people.csv -c config.json                       # 行の観測
sieve-crowd audit people.csv -c config.json --subject id          # 行の背後の人の観測
sieve-crowd audit people.csv -c config.json --findings-json a.json
```

- **同値類** — 準識別子の組が作るグループの数、最小のサイズ、一独りの行、k 未満の行、それぞれの千分率（切り捨て）、そして固定バケット（`1`、`2`、`3`、`4`、`5-9`、`10-49`、`50+`）ごとの行数。これらは `plan` が段階 0 の `before` として報告するのと同じ数です — 同じ名前、同じ数。
- **QI 列ごと** — 異なり値数（空セルを除く）、その列の中で値が一意な行の数、そしてその列を組から外したときに依然として k 未満にいる行の数。どの列がグルーピングを担っているかを、整数で示します。
- **同一対象の繰り返し**（`--subject COLUMN` 指定時） — k-匿名性は行について語りますが、人は複数の行にまたがれます。`audit` は人を数えます。対象ごとの行数とその分布、そして同値類ごとの **異なる対象数** — その中には `rows_overstated`（サイズは k 以上だが、異なる対象が k 人に届かない同値類に属する行）も含まれます。

subject 列は、設定にあり役割が `qi`/`sensitive` 以外の列（`id` 列が典型）である必要があり、それ以外は列名を述べて終了コード 2 で終わります。**空の subject 値は、1 行で 1 人の対象として扱われます** — 空のセル同士は同一人物かどうか判別できないため、空の行はすべて別々の対象（1 行 = 1 人）として、subject 関係の観測全体で一貫して扱います。`--subject` がなければ人の観測は行われず（`subject: null`）、その旨が報告に現れます。警告は観測の言い換えであって判定ではありません — `small_classes`（k 未満の行）と `subject_overstated`（見かけより少ない行）を、従来の `  - code: …` 書式で出し、終了コードは 0 のままです。表は読み取り専用で、書き込むのは任意の `--findings-json` だけ（schema 1、集計と列名のみ、**セルの値は一切出ません** — subject の値も含む）。`audit` にエントロピーは意図的にありません。対数は出力に浮動小数点を持ち込み、浮動小数点は環境によって末尾の桁が変わることがあります。整数は変わりません。

## 📄 scan: 表の全体像を 1 ページに（v0.8.0）

`sieve-crowd scan INPUT` は、"この表は、いまどう見えているか" を **1 枚の静的 HTML** にまとめます。読み物であってダッシュボードではありません。設定なしで実行すると、ヒントパックの候補から **仮の役割** を仮に置きます（v0.5.2 の候補順のいちばん上。候補のない列は `未割当（仮に keep）`、`id` の提案は「仮・出力から除く前提」であることが明示されます）。`-c CONFIG` を渡すと、宣言された役割をそのまま使い、ページは plan + audit を 1 度に読める形になります。何も実行されず、探索もしません。ページは CSP `default-src 'none'` でインラインスタイルのみ。ライト/ダーク対応、印刷・スマホ幅対応、色は情報を運ばない中性色です。セルの値は一切載らず、載るのは列名・件数・割合・ルール id・ファイル名・入力の SHA-256 だけ。同じ入力からは常にバイト同一（日時も環境の値も載りません）。`examples/people.csv` の設定なしの読み（英日）は、コマンドが書くそのままのバイトで `docs/samples/people.scan.en.html` と `docs/samples/people.scan.ja.html` としてリポジトリに同梱され、テストで固定され、版を上げるたびに再生成します。

```bash
sieve-crowd scan people.csv                                  # 仮の役割で people.scan.html へ
sieve-crowd scan people.csv -c config.json                   # 宣言された役割をそのまま
sieve-crowd scan people.csv -o report.html --lang ja         # 出力先と言語は自由
sieve-crowd scan people.csv --subject id                     # 行の背後の人も観測
```

ページは上から下へ読みます: 平易な文の要点。列の一覧（役割・根拠・候補ルール id・所見の件数 — `hidden_chars`、`japanese_era`、`leak`、`mixed_form`、`role_mismatch` を、code → 列名（コードポイント順）→ 既定の順の固定順で）。整数切り捨ての棒と数値によるグループの大きさ。列ごとの観測（`audit` のもの）。導出関係（`--no-derived` で省略）。同一対象の繰り返し（`--subject`、または対象列の候補名を載せた案内）。**設定の下書き**（未決列は `?`、それ以外は提案の一般化器）と `plan`/`run` のコマンド例。そして上の規則を明記した「この報告について」。各節は 1〜2 行の「この節の読み方」で始まり、文言は観測の側にとどまります — 「安全」「危険」「合格」「不合格」はどこにもありません。割合は千分率の切り捨て（整数演算のみ）を小数 1 桁の百分率で示します。

準識別子の候補が 1 つもなければ、グループ・観測・導出関係の節を省き、案内文に置き換えます — 終了コードは 0 のままです。`--k` は仮の役割用の k（既定 5。`-c` と併用時は plan と同じ規則で設定の k に優先）、`--max-rows` は audit と同じ意味（観測はすべての行を読み、表が大きいときはその旨を記録）、`--no-hidden-chars` で不可視文字の件数を省きます（件数は keep/qi/sensitive の列にのみ付き、仮の `id` 列には付きません）。出力先は `INPUT.scan.html` — `people.tar.csv` なら `people.tar.scan.html` — で、`--force` なしで無条件にアトミック上書きします。`-o PATH`、`-o -`（標準出力）も使えます。入力ファイルと設定ファイルは決して上書きせず、`-o` のない標準入力も拒否します（いずれも終了コード 2、何も書きません）。終了コード: 0 成功・1 入出力・2 使い方/設定/入力。悪意のある列名はマークアップを作れません（エスケープし、不可視・制御文字は `<U+XXXX>` で表示 — chartable の invisible 分類＋タブと改行を除く C0＋C1＋DEL）。120 コードポイントを超える列名は表示では省略し、下書きには全文が入ります。

## 🧪 ヒントパック（組み込みは既定オン）

`inspect` と `plan` は**ヒントパック**（JSON ファイル）を読み込みます。列への役割・一般化器の提案と値の形の検査を行い、匿名化には一切触れません。v0.5.1 から組み込みの `jp-basic` パックは**既定で読み込まれ**ます。`--no-builtin-hints` で除外します。`run` はパックを読みません（run のパスは v0.4.0 とバイト単位で同一です。`--no-builtin-hints` を付けてパックを指定しなければ、inspect のテンプレートまで v0.4.0 とバイト一致のままです）。

```bash
sieve-crowd inspect people.csv --config-out config.json              # 組み込み jp-basic を含めて提案
sieve-crowd plan   people.csv -c config.json    --findings-json f.json
sieve-crowd inspect people.csv --hint-pack my.json                   # 組み込み + my.json
sieve-crowd inspect people.csv --config-out t.json --no-builtin-hints  # v0.4.0 バイト一致の経路
```

- `--hint-pack FILE` — 組み込みに加えてパックを読み込む（複数指定可）。読み込み順は組み込みが先、次にコマンドラインの指定順。`findings` の `packs` / `pack_info` はこの順序に従います。候補の並びは独立の契約です（v0.5.2）: 根拠の強さ（name+value → value → name → stat）→ 役割（id → sensitive → qi・一覧にない役割は最後）→ ルール id の昇順 — 読み込み順にもパック内のルールの記述順にも従いません。`_suggest` は並べ替え後の先頭の候補に従います。
- `--no-builtin-hints` — `jp-basic` を除外し、指定したパックのみを使います（指定がなければ何も読み込まず、v0.4.0 バイト一致の出力のままです）。
- `--findings-json FILE` — 所見を JSON で書き出します。集計値と列名のみで、**セルの値は一切出ません**。`packs` は従来どおりパック id の配列。`pack_info` が読み込み順に `{id, version, source, sha256}` を加えます。`plan` ではパックが無くても導出分析の結果（`derived_summary`、v0.6.0）と不可視文字観測の要約（`hidden_chars_summary`、v0.7.1）が入ります。

**パック id とルール id は組み込みを含め全パックで一意です。** 組み込みと同じ `jp-basic`（または `jp-phone` などのルール id）を使うユーザーパックは終了コード 2 で拒否されます。組み込みを差し替えるには、`--no-builtin-hints` を付けてからその id を使ってください。

パック（`schema: 1`・`utf-8-sig` で読み込み・省略可能な `version` 文字列）はルールのリストです。各ルールは `when`（`column_names` と/または `value_shape` で列を照合）、省略可能な `suggest`（役割＋一般化器の設定・その列だけ `_suggest` に書き込まれる・v0.7.3 からはルールがその列で列名または値の合図を持るときだけ）、省略可能な `check`（`set`/`range`/`luhn`/`my_number`/`email_shape`・各 3 値: 一致/不一致/無法検査）、省略可能な `leak` フラグを持ちます。`value_shape` 言語は暴走を防ぐため意図的に閉じています: `#` は数字 1 桁、`@` は英字 1 桁、`\X` は X の字面エスケープ、量化子は `{m}`/`{m,n}` のみ（選択・入れ子なし・バックトラック暴走の余地なし）。

**値の照合は共有の文字表で折りたたむ（v0.7.1）。** `value_shape`・check・漏洩検査の値の入力は、照合の前に `sieve_crowd/chartable_v1.json` — Sieve Lens の正本のバイト完全な複製で、sha256 で固定され、読み込みのたびに再検証されます — で折りたたまれます。fold は固定マッピングで、適用順は: 不可視文字を取り除く → twins（キリル・ギリシャの同形文字）と全角 ASCII 範囲（`１２３` → `123`、`＠` → `@`）を置き換える → 折りたたみ空白（U+00A0・U+3000）を ASCII の空白にする → 形の照合（`value_shape` と漏洩検査）のときだけ折りたたみダッシュ（長音 `ー` を含む）を ASCII のハイフンにする。値の check はダッシュを畳みませんが、v0.7.5 から luhn の評価だけは例外的に、その後でもう一度だけダッシュ折りたたみを通し、半角の数字とハイフンだけからなる値に限ってダッシュを外して照合します（ほかの check は不変）。fold の中に Unicode データベースの参照は一切なく、同じ入力はどの Python のビルドでも同じ出力に折りたたまれます。印字可能 ASCII はすべて不変なので、純 ASCII の照合は 0.7.1 以前とバイト同一です。列名の照合は NFKC のまま（不変・v0.5.0 の決定により Unicode データベースに依存が残る — 既知の限界を参照）。

**漏洩検査（v0.5.1）。** `leak: true` のルールは、検査対象の列を *トークン* 単位で走査します。セルを空白と句読点で区切り（`-`・`+`・`@`・`.`・`_`・`%` は区切らない）、文章の途中に混ざった番号も見つけます（`03-1234-5678` はハイフンを除いた形でも照合します）。空白で区切られた断片は決して結合しません — `03 1234 5678` は**検出されません**（文書化した制約）。v0.7.1 からはセルをトークン化の前に折りたたむ（上記）ため、全角の数字やハイフン（`０９０－１２３４－５６７８`）や長音区切り（`090ー1234ー5678`）もトークンになり検出されます — 以前の「全角はトークンにならない」制約は折りたたみで解消されました。4096 文字を超えるセルは検査せず `skipped` として数えます。`plan` では宣言された役割が `keep`・`sensitive`・`qi` の列だけを検査し（id/drop は決して検査しません）、`inspect` は役割がないので全列を記録します。件数は `leaks[]`（`count`・`checked`・`skipped`、列には plan のみ `declared_role`）で報告され、`plan` では件数 1 以上のとき stderr の警告行と `findings.warnings` の `code: "leak"` 要素が出ます。`inspect` は代わりに候補と同じ書式の 1 行を出します。数字は「可能性」であって証明ではなく、警告は終了コードを変えません。

**keep 列 × 準識別子の導出関係（v0.6.0、`plan` のみ）。** keep 列 X と準識別子 Q の全ての組（X ≠ Q）を双方向で評価し、一方がもう一方をほぼ決めていないかを報告します: `reveals_qi`（X は出力にそのまま残るため、Q を一般化しても X から元の値が読めてしまう）と `implied_by_qi`（準識別子の値から keep 列の値がほぼ決まる）。評価された各方向は必ず次の 4 分類の 1 つになります: `unchecked`（比較レコードが 50 未満）、`trivial`（どちらかの列が一定、またはソースの値が全て一意 — 関係が情報を持たない）、`flagged`（支持 s が 50 以上で、違反 v — ソースの値では 1 つの値に定まらないレコード — が s の 1% 以下かつ超過分 s−m の 10% 以下。m はソースの異なる値の数）、`clear`（検査したが違反が多い）。flagged は stderr に `  - derived: …` 行として（ヒントパックの所見の直後に、自分の見出しは付けずに）出力され、`findings.warnings` には `code: "derived"` 要素（`column`・`declared_role`・`qi_column`・`relation`・`support`・`violations`）として入ります。トップレベルの `derived_summary` は 4 分類を数え、`unchecked + trivial + flagged + clear = 2 × (pairs − skipped_pairs)` が常に成り立ちます。値の比較はエンジンと同じ正規化（NFC＋前後の空白除去）で行い、空のセルは除外します。1 回の plan で評価する組は最大 400（残りは `skipped_pairs`）。`--no-derived` でこの報告全体を省きます。閾値はコード内定数で設定化しません。列名と件数のみで、セルの値は一切出ません。

**不可視文字の観測（v0.7.1、`plan` のみ）。** `plan` はさらに、すべての列のすべてのセルを、共有の文字表の不可視文字 — ゼロ幅（U+200B/200C/200D/2060/FEFF）・双方向制御・タグ文字・異体字選択子 — で走査します。列ごとに `rows`（1 文字以上を含む行数）・`chars`（総数）・`kinds`（ソート済みの種類名）を数えます。`keep`・`qi`・`sensitive` の列で `rows > 0` のとき 1 件ずつ、列名のソート順で警告が出ます — 例: `  - hidden_chars: "memo" (declared keep): 12 row(s) contain invisible characters (zero_width); they stay in the output`（keep 列）/ 「memo」（宣言 keep）: 12 行に不可視文字（zero_width）が含まれています。出力にそのまま残ります（qi 列は「見た目が同じ値が別のグループに分かれます」）。`id`/`drop` の列は要約の件数にのみ入ります（値がそのまま出力に残らないため）。これは観測であって変更ではありません — セルは 1 つも書き換えず、`run` は何も走査せず、セルの値もコードポイントも一切出力に現れません（出るのは種類の名前と件数だけ）。findings JSON は `warnings` 要素 `{code: "hidden_chars", column, declared_role, rows, chars, kinds}` とトップレベルの `hidden_chars_summary`（`columns_checked`・`columns_flagged`）を加えます。`--no-hidden-chars` で観測全体を省きます（既定オン）。

## ⚙️ 設定パラメータとオプション

| 設定項目 | 既定値 | 意味・説明 |
| :--- | :--- | :--- |
| `k` | 5 | 誰もが少なくとも k−1 人の似た者を持つ基準。大きいほど安全で一般化の度合いも強くなる |
| `l` | 任意 | どの群れにも少なくとも l 種類の機微な値があることを保証し、「全員が同じ診断名」を防ぐ |
| `max_suppression` | 0.05 (5%) | データ全体の解像度をもっと下げる代わりに、目立つ少数のレコードを除外（抑制）してよい最大割合 |
| `missing_value_policy` | `star` | `star`：空の準識別子は他の値と同じく `*` に一般化される。`suppress`：そのようなレコードは探索の前に除外され、`max_suppression` に算入される。 |
| 役割 (`role`) | — | `id`（削除または仮名化）・`qi`（一般化）・`sensitive`（残す）・`keep`（残す）・`drop`（削除） |
| 一般化器 (`type`) | — | `qi` 列に対して: `numeric`（`widths`、または不均一なカスタム `bins`）・`date`・`prefix`・`category`（階層）・`exact` |

主なコマンドラインオプション:

- `--dry-run`: データを書き出さず、匿名化の測定とリスク評価のみを実行
- `sieve-crowd plan people.csv -c config.json`: 探索空間・除外の上限・警告、そして keep 列 × 準識別子の導出関係（`--no-derived` で省略）と不可視文字の観測（`--no-hidden-chars` で省略）の事前見積り（探索なし、出力なし）
- `sieve-crowd audit people.csv -c config.json [--subject COLUMN]`: 現在の表を観測 — 同値類、QI 列ごとの観測、同一対象の繰り返し（整数のみ。探索なし、出力なし）
- `sieve-crowd scan people.csv [-c config.json] [-o report.html]`: 現在の状態を 1 枚の静的 HTML に — 仮の（または宣言された）役割、グループの大きさ、列ごとの観測、導出関係、同一対象の繰り返し、設定の下書き（探索なし、セルの値なし、同じ入力はバイト同一）
- `--lang ja`: 日本語のレシートを出力（既定は英語、JSON出力も可）
- `--in-format` / `--out-format`: 入出力形式の明示指定（csv, json, xml）
- `sieve-crowd keygen -o key.txt`: 仮名化（pseudonymize）用の暗号鍵を生成

終了コード:

- `0`: 成功
- `1`: 入出力エラー
- `2`: 設定エラー
- `3`: 拒否（目標とする匿名化レベルに到達せず出力を停止）

## ⚠️ 既知の限界と注意点

1. **モデルの前提** — Sieve Crowdが守るのは、`qi`（準識別子）に指定した属性を把握している攻撃者に対してです。想定外の補助情報による再識別を完全に防ぐ万能の盾ではありません。
2. **法務・プライバシー確認の代替ではない** — 個人情報保護法や各種ガイドラインに基づく法的・制度的な適合性を保証するものではなく、それを技術的に支援するツールです。
3. **Excel非対応** — 外部ライブラリに依存しないため、現行まではバイナリ形式の `.xlsx` を対象外としています（CSV / JSON / XML をご利用ください）。
4. **レコードのシャッフル** — 再識別リスクを最小化するため、出力される行順序は決定論的にシャッフルされます。
5. **列名の照合は依然として Unicode データベースに依存** — v0.7.1 から値の照合は固定の sha256 固定表で折りたたむため、実行環境の Unicode データに依存しなくなりました。一方、列**名**の照合は NFKC のまま（v0.5.0 の決定）で、Python の Unicode データベースの版が結果に影響しうる最後の箇所です（将来の版で列名の正規化も固定表にするかもしれません）。
