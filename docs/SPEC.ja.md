# Sieve Crowd 仕様書

バージョン0.2.0。[English](SPEC.md)

Sieve Crowdは、人に関する表（CSV・JSON・XML）を、部外者がすでに知り得る列について少なくとも *k* 件が似通った**群れ**にすべてのレコードが属する表に変え、
**できあがった表そのものを測定**します。オフライン、実行時の依存ゼロ、決定論的です。

## 1. モデル

| 用語 | 定義 |
|---|---|
| 役割 | 各列はちょうど1つの役割を持つ：`id`、`qi`、`sensitive`、`keep`、`drop`。役割のない列がある表は拒否される |
| 準識別子（QI） | `qi` の列。部外者がすでに知り得るもの。保証は、この宣言された集合に対して成り立つ |
| 群れ | 同値類：QIの値が等しいレコードの集まり（各値はNFC正規化し、前後の空白を除く） |
| k-匿名性 | どの群れも *k* 件以上（k ≥ 2） |
| l-多様性（distinct） | どの群れも、**各** `sensitive` 列について *l* 種類以上の値を持つ（l ≥ 1。l = 1 は要求なし） |
| リスク | レコードごとに 1/（群れの大きさ）。報告するのは、最大＝1/達成したk、平均＝群れの数÷レコード数 |

## 2. 処理の流れ

```
（CSV / JSON / XML）のバイト列 ─► 読み込み（UTF-8、ヘッダ）─► 一般化表 ─► 格子探索 ─►
  除外・列の処理・仮名化 ─► シャッフル ─► 測定 ─► レシート
```

形式は拡張子で判定し、`--in-format` / `--out-format` で上書きできます（8章）。どのアダプタも入力を同じ文字列の表に正規化するので、
処理の残りの部分は形式に依存しません。

1. **一般化表**：各QI・各段階について、異なる値ごとのラベルを作る（3章）
2. **格子探索**（4章）で、QIごとに段階を1つ選ぶ
3. **除外**：選んだ節で k や l を満たさない群れを、まるごと出力から除く（レコードの除外）
4. **列の処理**：`drop` と `id`＋`drop` の列は削除、`id`＋`pseudonymize` は置換（5章）、`qi` は一般化したラベル、`sensitive` と `keep` はそのまま
5. **シャッフル**（6章）
6. **測定**：探索とは独立したコード（`measure.py`）で出力の表を測定する。測定したkまたはlが要求を下回るか、レコードが残らなければ、
   実行は**拒否**され（`verification_failed`）、何も書き込まれない

拒否はエラーではなく結果です。`status = "refused"` と `reason` が返り、表は出力されません。

## 3. 一般化の階層

段階は0（値そのもの）からL（`*`、全体を隠す）まで。**各段階は前の段階を粗くしたもの**でなければなりません。2つの値がある段階で同じラベルなら、
それより上のすべての段階でも同じラベルです。探索はこの性質に依存し、各一般化器が強制またはテストします。

| `type` | パラメータ | 段階 |
|---|---|---|
| `numeric` | `widths`：正の整数で、各値は直前の値の**倍数**（既定 `[5,10,20,50,100]`） | 0 値 · j：幅 `widths[j-1]` の範囲（`30-34`、小数は `[30,35)`）· 最上位 `*`。空や解釈できない値は1段階目から `*` |
| `date` | なし | 0 `YYYY-MM-DD` · 1 `YYYY-MM` · 2 `YYYY` · 3 年代 `1990s` · 4 `*`。不正な日付は1段階目から `*` |
| `prefix` | `length` n ≥ 1 | 0 値 · j（1..n）：末尾j文字を `*` に · n+1 `*` |
| `category` | `hierarchy`：値 → [親, 祖父母, …] | 0 値 · 1..深さ 祖先（短い鎖は最後の祖先を繰り返す）· 最上位 `*`。階層にない値は1段階目から `*`。一一貫しない階層（1つの群が2つの親を持つ）や `*` という名前の祖先は拒否 |
| `exact` | なし | 0 値 · 1 `*`（除外のみ） |

## 4. 格子探索

節は、QIごとの段階を並べたベクトルです。`S(節)` を、k または l を満たさない群れに属するレコード数とします。
`S(節) ≤ 予算` のとき節は**許容**されます。予算＝`min(n − 1, ⌊max_suppression × n⌋)`。

*単調性*：許容される節からさらに一般化を進めた節も、必ず許容されます（併合された群れが違反するのは、その部分がすべて違反するときだけ）。
したがって、許容される節がある最小の高さ `h*` は、高さに対する二分探索で見つかります。最上位の節（すべて `*`）が実現可能性を決めます（そうでなければ `infeasible`）。

*目的関数*（辞書式）：正規化した損失 `Σ level_i / L_i` が最小、次に除外レコードが最少、次に段階ベクトルが最小。
第1段階で `h*` とその最良の節を求め、第2段階で、高さが `h*` 以上で損失がその節以下のすべての節を調べます（格子が20万節以下のとき）。
したがって結果は最適解です。評価の上限で第2段階が止まった場合、レシートの `refinement_truncated` に記録されます。

*上限*：`max_rows`（既定200,000）と `max_evals` 回の節の評価（既定20,000）。超えると `resource_limit_rows` / `resource_limit_search` で拒否します。
同順位の決め方もすべて決定論的です。

## 5. 直接識別子

`id` の列は、削除（`drop`、既定）または仮名化（`pseudonymize`）します。仮名は
`p-` ＋ base32(HMAC-SHA256(鍵, 列名 ‖ NUL ‖ NFC(値).strip())[:10])（小文字、16文字）で、空の値は空のままです。
鍵は16バイト以上の乱数の16進表記（`sieve-crowd keygen`）で、設定やレシートには含まれません。同じ鍵なら同じ仮名になるので、
同じ鍵で作った複数の公開物は互いに結びつけられます。

## 6. 行の順序

出力の行は、SplitMix64でシャッフルします（Fisher–Yates、`below(n)` は棄却サンプリング）。`shuffle_seed` の既定は0です。
入力の順序を保つこと（`--keep-order`）は**緩和**で、レシートの `relaxations` に記録されます。

## 7. 設定

```json
{ "k": 5, "l": 2, "max_suppression": 0.05,
  "columns": { "<列名>": { "role": "...", ... } } }
```

厳格に検証します。未知のキー、未知の役割、役割が `?`（`inspect` が書くひな形）、`k < 2`、[0, 1) の外の `max_suppression`、`qi` 列がない、
`sensitive` 列のない `l > 1`、鍵のない `pseudonymize`、表の列と設定の不一致は拒否されます（メッセージには列名を含み、セルの値は含みません）。
設定はコマンドラインで上書きできます（`--k`、`--l`、`--max-suppression`）。`_` で始まるキーはコメントとして無視されます。

## 8. コマンドライン

| コマンド | 目的 |
|---|---|
| `inspect FILE [--config-out F] [--in-format F] [--lang]` | 列ごとの異なる値の数、空の数、値が一意な割合、見かけの形と、列名と値に基づく*ヒント*（例：「直接識別子のようです」）を表示し、役割 `?` と `_hint` コメントを含むひな形を書く。役割は自動では割り当てない |
| `keygen -o F` | ランダムな鍵を書く（ファイルモード600）。`--force` なしに既存のファイルを置き換えない |
| `run FILE -c CONFIG (-o OUT \| --dry-run)` | 匿名化。オプション：`--key-file --k --l --max-suppression --keep-order --shuffle-seed --lang --delimiter --in-format --out-format --max-rows --max-evals --report-json --quiet --force` |

出力先が入力ファイルになることはなく、既存の出力ファイルには `--force` が必要で、書き込みは原子的に行われます。終了コード：
0 成功 · 1 入出力 · 2 設定・使い方・不正な入力 · 3 拒否。入力はUTF-8（BOM可）、出力は改行 `\n` のUTF-8です。

### 形式

対応するのは CSV・JSON・XML だけです。Excel（`.xlsx`／`.xls`）は意図的に対応していません。ファイルの形式は拡張子（`.csv`、`.json`、`.xml`）で判定し、
`--in-format` / `--out-format` で上書きします（stdin／stdout や拡張子のない名前を曖昧でなくします。`-` は指定がなければ CSV）。`--delimiter` は CSV 専用で、
JSON／XML に対して指定すると拒否されます。

* **CSV** — ヘッダ行＋レコード（引用符付きフィールドや区切り文字の変更は Python の `csv` で対応）。
* **JSON** — レコードの配列 `[{"列": 値, ...}, ...]`（最初のレコードが列の順序を決め、すべてのレコードが同じ列集合でなければならない）または
  明示形 `{"header": [...], "rows": [[...], ...]}` のどちらか。セルの値：文字列はそのまま、数値は 10 進のテキストに（`30` → `"30"`、`30.0` → `"30.0"`）、
  真理値は `true`/`false` に、`null` は空のセルに。拒否するもの：入れ子のオブジェクト／配列、重複したキー、規格外の `NaN`／`Infinity`、
  無限大にあふれる数。出力はレコードの配列（2スペースのインデント）で、空のセルは `null` ではなく `""` と書かれます。
* **XML** — ルート要素の名前（と属性）は無視します。ルートの直接の子がレコード、その中の各フィールドは、列名を `name` 属性に持つ空かテキストの要素です
  （列名は任意の文字列なので、要素名にはできないため）。拒否するもの：DOCTYPE 宣言（「billion laughs」のようなエンティティ展開攻撃の余地をなくすため。
  DTD がなければエンティティは定義できない）、名前空間、入れ子のフィールド、予定外の属性、重複・欠落・余分な列、要素であるべき場所のテキスト。
  出力は `<table><row><f name="列">値</f>...</row></table>` で、2スペースのインデント。空のセルは自己閉じのフィールドです。XML 1.0 で表現できない値
  （制御文字）は、行と列の名前を添えて拒否されます（値そのものは出しません）。

同じ論理表は、どの形式で運んでも同じ結果になります（テストで固定した不変条件）。そのため、ある形式で読み、別の形式で書くことができます：
`run people.csv -c config.json -o people_safe.json`。

## 9. レシート

機械可読（`--report-json`、英語の識別子）と人間向け（`--lang en|ja`）を、同じオブジェクトから作ります。内容は、バージョン、Unicodeデータのバージョン、
`status`、`reason`（拒否のとき）、入力の大きさ、`io`（`input_format`、表を書くときは `output_format`）、設定、結果（出力件数・除外件数・割合）、
プライバシー（QIの一覧、`before`：入力でQI列について似た者のいない1件だった件数、`k_requested`、`k_achieved`、群れの数、
小さい5つの群れの大きさ、群れに1件だけのレコード数、リスクの最大と平均、`sensitive` 列ごとの達成した多様性）、情報の損失（高さ／最大の高さ、精度の損失）、
列ごとの処理（QIは段階と説明、`keep` 列は値が一意な割合）、行の順序、`relaxations`、探索の統計、`verification` です。
**セルの値はレシートに現れません**。列名と集計値だけです。

## 10. テストで確認する不変条件

| | |
|---|---|
| — | 出力のkの測定値が要求k以上、多様性の測定値がl以上（テストでは素朴な数え上げで確認） |
| — | 探索の結果が、格子全体に対する総当たりの結果と一致する（4章の目的関数） |
| — | 一般化を1段階進めても許容性が保たれる（単調性） |
| — | すべての一般化器で、各段階が前の段階を粗くしている（ランダムな値でテスト） |
| — | 同じ表・設定なら同じ出力。SplitMix64と仮名のベクトルを固定（`tests/vectors`） |
| — | レシートにセルの値が含まれない |
| — | 値のNFCとNFDの表記が1つの群れになる |
| — | 同じ論理表なら、運んだ形式に関わらず同じ出力になる。JSONとXMLは往復する |

## 11. 実装上の注意

* 1回の実行が支えるのは、「各レコードは、宣言されたQI列について、少なくとも *k* 件の似た者の1つである」という主張です。役割 `keep` の列は
  このモデルの外にあります。識別子のような列に気づきやすいよう、レシートに値が一意な割合を示します。
* l-多様性はdistinct版です。レコードの除外は群れをまるごと除くもので、値を部分的に隠すものではありません。
* 欠損値や解釈できない値は直接 `*` に一般化されるので、低い段階では独立した群れになります。
* CSV・JSON・XML（UTF-8、ヘッダ行、1つの表）。引用符付きのフィールドや区切り文字の変更は、Pythonの `csv` で対応します。
  JSONとXMLのアダプタは同じ文字列の表に正規化するので、エンジンは形式を知りません。
* 速度の目安：10万行×QI4列で、一般的なノートPCで約6秒。
* 乱数を使うのはシャッフルだけで、SplitMix64（自前の実装、移植可能）を使います。

## 付録　独自に決めたこと

| # | 決定 | 理由 |
|---|---|---|
| — | k-匿名性＋distinct l-多様性を、出力で測定する | テキストの匿名化と違い、数えられる保証になる |
| — | すべての列に役割が必要。ひな形は `?` で、そのままでは拒否 | 何が機微かを推推測しない |
| — | 拒否を第一級の結果にする | 安全に見えるだけの表を出さない |
| — | 大域的な再符号化＋群れ単位の除外 | 単純で、単調で、正しさを証明しやすい |
| — | 入れ子の階層のみ（検証する） | 二分探索に単調性が必要 |
| — | 既定でシャッフル。順序の保持は記録される緩和 | 入力の順序が個人を示すことが多い |
| — | 仮名化は選択式で、鍵付き、結びつけ可能と明記 | 仮名化は匿名化ではない |
| — | 比較前にNFCと前後の空白除去 | 見た目が同じ値は同じ群れにする |
| — | 上限：20万行、2万回の評価 | 時間を有限にする |
| — | レシートは集計値と列名のみ | レシートを共有できる |
| — | `inspect` はヒントを出すが役割は決めない。レシートに処理前後の状況を示す | 読み手が気にする言葉で価値を説明しつつ、代わりに推測はしない |
| — | 形式は拡張子で判定し、`--in-format` / `--out-format` で上書き。Excel は対応しない | 予測できるファイルと曖昧さのない例外処理、外部の読み込みライブラリを入れない |
| — | JSON はレコード配列か明示形。セルは入口で文字列に正規化 | エンジンは形式に依存せず、厳格な拒否が表の曖昧さをなくす |
| — | XML のフィールドは `name` 属性を持つ。DOCTYPE と名前空間は全面拒否 | 列名は任意の文字列（要素名にはできない）であり、プライバシーの道具がエンティティ展開する入力を解釈してはならない |
| — | 欠損はどの形式でも空のセル（`null` → `""`、空要素 → `""`） | 往復が安定し、出力が `null` を作らない |
| — | 形式非依存性をテストされた不変条件にする | 保証が、表を運んだ形式に依存してはならない |
