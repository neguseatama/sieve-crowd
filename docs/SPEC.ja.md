# Sieve Crowd 仕様書

バージョン0.7.0。[English](SPEC.md)

Sieve Crowdは、人に関する表（CSV・JSON・XML）を、部外者がすでに知り得る列について少なくとも *k* 件が似通った**群れ**にすべてのレコードが属する表に変え、
**できあがった表そのものを測定**します。オフライン、実行時の依存ゼロ、決定論的です。

## 1. モデル

| 用語 | 定義 |
|---|---|
| 役割 | 各列はちょうど1つの役割を持つ：`id`、`qi`、`sensitive`、`keep`、`drop`。役割のない列がある表は拒否される |
| 準識別子（QI） | `qi` の列。部外者がすでに知り得るもの。保証は、この宣言された集合に対して成り立つ |
| 群れ | 同値類：QIの値が等しいレコードの集まり（各値はNFC正規化し、前後の空白を除く） |
| k-匿名性 | どの群れも *k* 件以上（k ≥ 2） |
| l-多様性（distinct） | どの群れも、**各** `sensitive` 列について *l* 種類以上の値を持つ（l ≥ 1。l = 1 は要求なし） |
| リスク | レコードごとに 1/（群れの大きさ）。報告するのは、最大＝1/達成したk、平均＝群れの数÷レコード数 |

## 2. 処理の流れ

```
（CSV / JSON / XML）のバイト列 ─► 読み込み（UTF-8、ヘッダ）─► 一般化表 ─► 格子探索 ─►
  除外・列の処理・仮名化 ─► シャッフル ─► 測定 ─► レシート
```

形式は拡張子で判定し、`--in-format` / `--out-format` で上書きできます（8章）。どのアダプタも入力を同じ文字列の表に正規化するので、
処理の残りの部分は形式に依存しません。

1. **一般化表**：各QI・各段階について、異なる値ごとのラベルを作る（3章）
2. **格子探索**（4章）で、QIごとに段階を1つ選ぶ
3. **除外**：選んだ節で k や l を満たさない群れを、まるごと出力から除く（レコードの除外）
4. **列の処理**：`drop` と `id`＋`drop` の列は削除、`id`＋`pseudonymize` は置換（5章）、`qi` は一般化したラベル、`sensitive` と `keep` はそのまま
5. **シャッフル**（6章）
6. **測定**：探索とは独立したコード（`measure.py`）で出力の表を測定する。測定したkまたはlが要求を下回るか、レコードが残らなければ、
   実行は**拒否**され（`verification_failed`）、何も書き込まれない

拒否はエラーではなく結果です。`status = "refused"` と `reason` が返り、表は出力されません。

## 3. 一般化の階層

段階は0（値そのもの）からL（`*`、全体を隠す）まで。**各段階は前の段階を粗くしたもの**でなければなりません。2つの値がある段階で同じラベルなら、
それより上のすべての段階でも同じラベルです。探索はこの性質に依存し、各一般化器が強制またはテストします。

| `type` | パラメータ | 段階 |
|---|---|---|
| `numeric` | `widths`：正の整数で、各値は直前の値の**倍数**（既定 `[5,10,20,50,100]`）— または `bins`：厳密に増加する内部境界のリストで、最初と最後のビンは開いた区間（`widths` と `bins` の併用は不可） | 0 値 · `widths`：j：幅 `widths[j-1]` の範囲（`30-34`、小数は `[30,35)`）· `bins`：1 カスタム区間（整数は `<0`、`0-19`、`65+`、小数は `<0.5`、`[0.5,20)`、`>=65`）· 最上位 `*`。空や解釈できない値は1段階目から `*`。整数列に小数の `bins` 境界は拒否 |
| `date` | なし | 0 `YYYY-MM-DD` · 1 `YYYY-MM` · 2 `YYYY` · 3 年代 `1990s` · 4 `*`。不正な日付は1段階目から `*` |
| `prefix` | `length` n ≥ 1 | 0 値 · j（1..n）：末尾j文字を `*` に · n+1 `*` |
| `category` | `hierarchy`：値 → [親, 祖父母, …] | 0 値 · 1..深さ 祖先（短い鎖は最後の祖先を繰り返す）· 最上位 `*`。階層にない値は1段階目から `*`。一一貫しない階層（1つの群が2つの親を持つ）や `*` という名前の祖先は拒否 |
| `exact` | なし | 0 値 · 1 `*`（除外のみ） |

## 4. 格子探索

節は、QIごとの段階を並べたベクトルです。`S(節)` を、k または l を満たさない群れに属するレコード数とします。
`S(節) ≤ 予算` のとき節は**許容**されます。予算＝`min(n − 1, ⌊max_suppression × n⌋)`。

*単調性*：許容される節からさらに一般化を進めた節も、必ず許容されます（併合された群れが違反するのは、その部分がすべて違反するときだけ）。
したがって、許容される節がある最小の高さ `h*` は、高さに対する二分探索で見つかります。最上位の節（すべて `*`）が実現可能性を決めます（そうでなければ `infeasible`）。

*目的関数*（辞書式）：正規化した損失 `Σ level_i / L_i` が最小、次に除外レコードが最少、次に段階ベクトルが最小。
第1段階で `h*` とその最良の節を求め、第2段階では、高さが `h*` 以上で損失がその節以下の領域を、最も一般的な節から
深さ優先で歩きます（格子が20万節以下のとき）。枝刈りは3つ。これ以上 `h*` に届かない部分木、現時点の最良解より
重い部分木、そして拒否された節とその下位のすべての節（単調性により、除外を減らしても群れは直らない）です。
領域を材料化することはなく、結果は最適解です。評価の上限で第2段階が止まった場合、レシートの `refinement_truncated`
に記録されます。評価数は参考値で、版により異なることがあります。

*上限*：`max_rows`（既定200,000）と `max_evals` 回の節の評価（既定20,000）。超えると `resource_limit_rows` / `resource_limit_search` で拒否します。
同順位の決め方もすべて決定論的です。

## 5. 直接識別子

`id` の列は、削除（`drop`、既定）または仮名化（`pseudonymize`）します。仮名は
`p-` ＋ base32(HMAC-SHA256(鍵, 列名 ‖ NUL ‖ NFC(値).strip())[:10])（小文字、16文字）で、空の値は空のままです。
鍵は16バイト以上の乱数の16進表記（`sieve-crowd keygen`）で、設定やレシートには含まれません。同じ鍵なら同じ仮名になるので、
同じ鍵で作った複数の公開物は互いに結びつけられます。

## 6. 行の順序

出力の行は、SplitMix64でシャッフルします（Fisher–Yates、`below(n)` は棄却サンプリング）。`shuffle_seed` の既定は0です。
入力の順序を保つこと（`--keep-order`）は**緩和**で、レシートの `relaxations` に記録されます。

## 7. 設定

```json
{ "k": 5, "l": 2, "max_suppression": 0.05, "missing_value_policy": "star",
  "columns": { "<列名>": { "role": "...", ... } } }
```

厳格に検証します。未知のキー、未知の役割、役割が `?`（`inspect` が書くひな形）、`k < 2`、[0, 1) の外の `max_suppression`、
`star` か `suppress` 以外の `missing_value_policy`、`qi` 列がない、`sensitive` 列のない `l > 1`、鍵のない `pseudonymize`、
表の列と設定の不一致は拒否されます（メッセージには列名を含み、セルの値は含みません）。
設定はコマンドラインで上書きできます（`--k`、`--l`、`--max-suppression`、`--missing-value-policy`）。
`_` で始まるキーはコメントとして無視されます。

`missing_value_policy` は、準識別子の値が空（正規化と前後の空白除去の後）であるレコードの扱いを決めます。
`star`（既定）はそのまま残します。値は他の値と同様に扱われ、1段階目から `*` に一般化されるので、欠損レコードは
低い段階で独立した群れになります。`suppress` は探索の前にそのようなレコードを除き、除外の予算に算入します。
それだけで予算を超えるときは `missing_exceeds_budget` で拒否します。placeholder（埋め値）の方針は意図的に
提供しません。埋めた値は、欠損パターンそのものを準識別子にしてしまうためです。

## 8. コマンドライン

| コマンド | 目的 |
|---|---|
| `inspect FILE [--config-out F] [--in-format F] [--lang]` | 列ごとの異なる値の数、空の数、値が一意な割合、見かけの形と、列名と値に基づく*ヒント*（例：「直接識別子のようです」）を表示し、役割 `?` と `_hint` コメントを含むひな形を書く。役割は自動では割り当てない |
| `keygen -o F` | ランダムな鍵を書く（ファイルモード600）。`--force` なしに既存のファイルを置き換えない |
| `run FILE -c CONFIG (-o OUT \| --dry-run)` | 匿名化。オプション：`--key-file --k --l --max-suppression --missing-value-policy --keep-order --shuffle-seed --lang --delimiter --in-format --out-format --max-rows --max-evals --report-json --quiet --force` |
| `plan FILE -c CONFIG` | 実行前の事前プロファイル。探索の前に：オプション `--k --l --max-suppression --missing-value-policy --max-rows --max-evals --key-file --lang --delimiter --in-format --report-json --quiet --hint-pack --no-builtin-hints --no-derived --no-hidden-chars --findings-json` |
| `audit FILE -c CONFIG` | 表を今のまま観測 — 一般化も判定も書き込みもしない（§13）：オプション `--subject --lang --delimiter --in-format --max-rows --max-evals --findings-json --quiet` |
| `scan INPUT [-c CONFIG] [-o OUT\|-]` | 表の今の状態を 1 枚の静的 HTML に（§15）：オプション `--hint-pack --no-builtin-hints --no-hidden-chars --subject --k --max-rows --no-derived --lang` |

plan はそれ自身がレシートです（`status = "plan"`）。報告するのは**正確な値だけ**です。格子の大きさと最大の高さは設定だけから決まり
（各QIは `levels + 1` 個の節を生む）、除外の上限は `min(n − 1, ⌊max_suppression × n⌋)`、列ごとの観察と段階0の群れの統計
（群れの数、一独りの数、k 未満の群れに属するレコード数）は表を1回読むだけで得られ、各 `sensitive` 列の異なる値の数が l の実現可能性を決めます。
推定はしません。探索そのものについての予測は行いません。警告（コードとパラメータ）：`rows_over_limit`、`k_unreachable`、
`l_unreachable`、`budget_zero`（除外が許されないのに段階0で既に小さすぎる群れがある）、`missing_over_budget`（`suppress` 方針で、
準識別子が空のレコードが予算を超える）、`lattice_large`（改善フェーズの上限を超えるため
第2段階が省略される）、`evals_tight`（格子が `max_evals` を超える）、`many_singletons`（段階0で一独りが 50% 以上 — 発見的手法）。
現在の方針の下で準識別子が空のレコード数も報告します。v0.6.0 からは keep 列 × 準識別子の導出分析（§12）も実行します（`--no-derived` で省略）。
v0.7.1 からは不可視文字の観測（§14）も実行します（`--no-hidden-chars` で省略）。
plan は探索を実行せず、表を書かず、終了コード 0 で終わります。

出力先が入力ファイルになることはなく、既存の出力ファイルには `--force` が必要で、書き込みは原子的に行われます。終了コード：
0 成功 · 1 入出力 · 2 設定・使い方・不正な入力 · 3 拒否。入力はUTF-8（BOM可）、出力は改行 `\n` のUTF-8です。

### 形式

対応するのは CSV・JSON・XML だけです。外部ライブラリに依存しないため、現行までは Excel（`.xlsx`／`.xls`）を対象外としています。ファイルの形式は拡張子（`.csv`、`.json`、`.xml`）で判定し、
`--in-format` / `--out-format` で上書きします（stdin／stdout や拡張子のない名前を曖昧でなくします。`-` は指定がなければ CSV）。`--delimiter` は CSV 専用で、
JSON／XML に対して指定すると拒否されます。

* **CSV** — ヘッダ行＋レコード（引用符付きフィールドや区切り文字の変更は Python の `csv` で対応）。
* **JSON** — レコードの配列 `[{"列": 値, ...}, ...]`（最初のレコードが列の順序を決め、すべてのレコードが同じ列集合でなければならない）または
  明示形 `{"header": [...], "rows": [[...], ...]}` のどちらか。セルの値：文字列はそのまま、数値は 10 進のテキストに（`30` → `"30"`、`30.0` → `"30.0"`）、
  真理値は `true`/`false` に、`null` は空のセルに。拒否するもの：入れ子のオブジェクト／配列、重複したキー、規格外の `NaN`／`Infinity`、
  無限大にあふれる数。出力はレコードの配列（2スペースのインデント）で、空のセルは `null` ではなく `""` と書かれます。
* **XML** — ルート要素の名前（と属性）は無視します。ルートの直接の子がレコード、その中の各フィールドは、列名を `name` 属性に持つ空かテキストの要素です
  （列名は任意の文字列なので、要素名にはできないため）。拒否するもの：DOCTYPE 宣言（「billion laughs」のようなエンティティ展開攻撃の余地をなくすため。
  DTD がなければエンティティは定義できない）、名前空間、入れ子のフィールド、予定外の属性、重複・欠落・余分な列、要素であるべき場所のテキスト。
  出力は `<table><row><f name="列">値</f>...</row></table>` で、2スペースのインデント。空のセルは自己閉じのフィールドです。XML 1.0 で表現できない値
  （制御文字）は、行と列の名前を添えて拒否されます（値そのものは出しません）。

同じ論理表は、どの形式で運んでも同じ結果になります（テストで固定した不変条件）。そのため、ある形式で読み、別の形式で書くことができます：
`run people.csv -c config.json -o people_safe.json`。

## 9. レシート

機械可読（`--report-json`、英語の識別子）と人間向け（`--lang en|ja`）を、同じオブジェクトから作ります。内容は、バージョン、Unicodeデータのバージョン、
`status`、`reason`（拒否のとき）、入力の大きさ、`io`（`input_format`、表を書くときは `output_format`）、設定、結果（出力件数・除外件数・割合、
`suppress` 方針では探索前に除いた件数 `missing_suppressed`）、
プライバシー（QIの一覧、`before`：入力でQI列について似た者のいない1件だった件数、`k_requested`、`k_achieved`、群れの数、
小さい5つの群れの大きさ、群れに1件だけのレコード数、リスクの最大と平均、`sensitive` 列ごとの達成した多様性）、情報の損失（高さ／最大の高さ、精度の損失）、
列ごとの処理（QIは段階と説明、`keep` 列は値が一意な割合）、行の順序、`relaxations`、探索の統計、`verification` です。
**セルの値はレシートに現れません**。列名と集計値だけです。

除外があったときは、レシートに `diagnostics.suppression` が付きます。除外の上限（予算）、除かれた群れとレコードの数、群れの大きさのヒストグラム
（最大20件）、除かれた群れの *k 未満* と *l 多様性不足* への分類（`sensitive` 列ごと）、そして `one_level_further`（まだ最上位でない各QIについて、
1段階粗くしたときに救われる除外レコードの数）です。拒否には理由別の `diagnostics` が付きます。`infeasible`（レコード数と k、`sensitive` 列ごとの
異なる値の数と l）、`resource_limit_search`（格子の大きさ、QIごとの段数、使用した評価）、`verification_failed`（出力の群れの大きさのヒストグラム、
列ごとの l 不足、テストした段階ベクトル）、`missing_exceeds_budget`（レコード数・欠損レコード数・予算）。診断が名指すのは列名だけで、大きさと件数のみを報告します。
個々の群れのラベル（セルの値から導かれるもの）は
決して報告しません。

## 11. 実装上の注意

* 1回の実行が支えるのは、「各レコードは、宣言されたQI列について、少なくとも *k* 件の似た者の1つである」という主張です。役割 `keep` の列は
  このモデルの外にあります。識別子のような列に気づきやすいよう、レシートに値が一意な割合を示します。
* l-多様性はdistinct版です。レコードの除外は群れをまるごと除くもので、値を部分的に隠すものではありません。
* 欠損値や解釈できない値は直接 `*` に一般化されるので、低い段階では独立した群れになります。`missing_value_policy` が
  `suppress` のときは、代わりにQI値が空のレコードを探索の前に、同じ予算内で除きます。
* `numeric` のカスタム `bins` は、設定された境界の値をそのままラベルに使います。列の整数／小数モード（`widths` と同様にデータから決める）は、
  `0-19` 形と `[0,20)` 形のどちらを選ぶかだけに関わります。
* plan モードは run と設定の検証を共有し、表を1回読みます。格子探索は決して実行しません。
* audit モードは run と設定の検証を共有し、エンジンの `_norm` を使います。CLI では関数レベルで import するため、
  `run`/`plan`/`inspect` はこのモジュールを読み込みません（§13）。
* CSV・JSON・XML（UTF-8、ヘッダ行、1つの表）。引用符付きのフィールドや区切り文字の変更は、Pythonの `csv` で対応します。
  JSONとXMLのアダプタは同じ文字列の表に正規化するので、エンジンは形式を知りません。
* 速度の目安：10万行×QI4列で、一般的なノートPCで約6秒。
* 乱数を使うのはシャッフルだけで、SplitMix64（自前の実装、移植可能）を使います。

## 12. ヒントパック（inspect/plan のみ）

ヒントパックは `inspect` と `plan` のための JSON オブジェクト（`schema: 1`・`utf-8-sig` で読み込み・省略可能な `version` 文字列）で、役割の提案と値の形の検査を行います。v0.5.1 から組み込み `jp-basic` パックは**既定で読み込まれます**。`--no-builtin-hints` で除外します。`run` はヒントパックモジュールを import せず、`--no-builtin-hints` を付けてユーザーパックを与えなければ inspect/plan の出力は v0.4.0 とバイト単位で同一です。

コマンドライン（inspect/plan のみ）: `--hint-pack FILE`（複数指定可）、`--no-builtin-hints`（組み込みを除外）、`--findings-json FILE`（所見・`--report-json` とは別ファイル）。読み込み順は組み込みが先、次にコマンドラインの指定順で、`findings` の `packs` / `pack_info` はこの順序に従います。候補の並びは読み込み順とは独立の契約です（v0.5.2）: 根拠の強さ（name+value → value → name → stat）→ 役割（id → sensitive → qi・この一覧にない役割は最後）→ ルール id の昇順（文字列の昇順）。テンプレートの `_suggest` は並べ替え後の先頭の候補に従います。同じパックの中でルールの記述順を入れ替えても、複数パックの渡し順を入れ替えても、候補の並びと `_suggest` は変わりません（`packs` / `pack_info` は渡し順の記録のまま）。v0.7.3 から、提案はルールがその列で列名または値の合図を持つときにだけ書き込まれます — 列名が一致しない leak ルールはトークン走査は行いますが、列に提案を掛けることはありません（この扉がないと、提案を持つ leak ルールが走査対象の全列に提案を掛けることになります）。

**一意性。** パック id とルール id は組み込みを含め全パックで一意です。重複は `ConfigError`（終了コード 2）で、メッセージはファイル名と衝突した id を示し、組み込みを差し替える方法として `--no-builtin-hints` を案内します。メッセージにセルの値は一切出ません。

パックはルールのリストです。ルールの `when` は `column_names`（NFKC＋小文字化・旧 `hint()` の照合に NFKC を足したもの・旧 `hint()` 自体は不変）と/または `value_shape` で列を照合します。`value_shape` 言語は閉じた集合: `#` 数字・`@` 英字・`\X` 字面・量化子は `{m}`/`{m,n}` のみ（選択・入れ子なし・暴走なし）。ルールは `check`（`set`/`range`/`luhn`/`my_number`/`email_shape`・3 値: 一致/不一致/無法検査・Luhn とマイナンバーの検査数字は公式テストベクトル固定）、`leak`、`suggest`（役割＋一般化器設定・その列だけ `_suggest`/`_candidates` に書き込まれる・v0.7.3 からは列名か値の合図があるときだけ）を持ちます。証拠の強さの優先度は name+value → value → name → stat。

**値の照合は共有の文字表で折りたたむ（v0.7.1）。** `value_shape`・check・漏洩検査の値の入力は、照合の前に `sieve_crowd/chartable_v1.json`（§14）で折りたたみます: `value_shape` と漏洩検査は `dashes=True`（形の照合 — 長音と他の折りたたみダッシュが `-` になり、`090ー1234ー5678` はハイフン付き 1 トークンになって既存のハイフン除去照合が働く）、値の check は `dashes=False`（v0.7.5 から luhn の評価だけは例外的に、その後でもう一度 `dashes=True` の折りたたみを通し、半角の数字と `-` だけからなる値に限ってダッシュを外して照合します — ほかの check は不変・ダッシュなしの値は同じ経路を通るので不変）。折りたたみは固定マッピングなので、純 ASCII の照合は 0.7.1以前とバイト同一で、全角の数字・記号・長音ダッシュ・不可視文字が照合に届くようになります（v0.5.2 の「全角を扱えない」限界の解消）。ダッシュ入りの全角郵便番号は `#{7}` の形には一致しません（ハイフンが残るため。ダッシュの除去は形の言語にない — ハイフンを除いて照合するのは漏洩検査だけで、`jp-zip` は leak ルールではない）。v0.7.3 からダッシュ形は専用のルール `jp-zip-hyphen`（`#{3}-#{4}`。`prefix` length 4 を提案 — `#{7}` と同じ 4 段の部分レベルで残り桁数 6・5・4・3 も同じ、ダッシュは決して隠れない。長さ 5 だとダッシュだけが隠れる冗長な段が加わる）になりました。全角の `１２３－４５６７` は折りたたみを経てこの形に届きます。列名の照合は NFKC のまま（不変・v0.5.0 の決定による、Unicode データベースに依存する最後の箇所）。

**漏洩検査（v0.5.1）。** `leak: true` のルールは、検査対象の列をトークン単位で走査します。セルを空白と句読点で区切る（`-` `+` `@` `.` `_` `%` は区切らない）ので、文章の途中に混ざった番号も見つかります。ハイフン付きトークンはハイフンを除いた形でも照合します（`03-1234-5678` → `0312345678`）。空白で区切られた断片は決して結合しません（`03 1234 5678` は検出されない・文書化した制約）。v0.7.1 からはセルをトークン化の前に折りたたむ（dashes=True）ため、全角の数字やハイフン（`０９０－１２３４－５６７８`）や長音区切り（`090ー1234ー5678`）もトークンになり検出されます — 以前の「全角はトークンにならない」制約は折りたたみで解消されました（§14）。4096 文字を超えるセルは検査せず `skipped` として数えます。`plan` では宣言された役割が `keep`・`sensitive`・`qi` の列だけを検査し（id/drop は決して検査しません）、`inspect` は役割がないので全列を記録します。件数は `columns.<列>.leaks[]` に `{pack, rule, count, checked, skipped}` で入ります（`checked` は実際に走査した空でないセル数・件数または skipped が正のとき要素が出ます）。`plan` では列に `declared_role` が付き、件数 1 以上で stderr の警告行と `warnings` の `code: "leak"` 要素（列名・宣言役割・パック・ルール・件数・checked）が出ます。`inspect` は代わりに候補と同じ書式の 1 行を出します。数字は「可能性」であって証明ではなく、警告は終了コードを変えません。

**keep 列 × 準識別子の導出関係（v0.6.0、plan のみ）。** パックとは独立に、`plan` は keep 列 X と準識別子 Q の全ての組（X ≠ Q・表の列順）をクロスし、両方が空でない行（値の比較はエンジンの `_norm`: NFC＋前後の空白除去）の 1 回のクロス集計から双方向を評価します。`reveals_qi` ＝ keep 列が生の準識別子の値をほぼ決める（X はそのまま出るので Q を一般化しても隠せない）。`implied_by_qi` ＝ 準識別子の値が keep 列の値をほぼ決める。方向ごとに、s ＝ 比較レコード数、m ＝ ソースの異なる値の数、v ＝ ソースの値では 1 つの値に定まらないレコード数（s − 各グループの最大 target 計数の和）として、s < 50 なら `unchecked`、どちらかの列が一定か s − m = 0（ソースが一意・単なる一意性で関係ではない）なら `trivial`、s ≥ 50 かつ s − m > 0 かつ 100·v ≤ s かつ 10·v ≤ s − m なら `flagged`、それ以外は `clear`。閾値（50・1%・10%）と `PAIR_LIMIT = 400` はコード内定数で、上限を超えた組は `skipped_pairs` に数えて打ち切ります。flagged は stderr の `  - derived: …` 行（ヒントパックの所見の直後・自分の見出しなし・`--quiet` で抑制）と `warnings` 要素 `{code: "derived", column, declared_role, qi_column, relation, support, violations}` になり、findings のトップレベルには `derived_summary = {pairs, skipped_pairs, unchecked, trivial, flagged, clear}` が加わり、不変条件 `unchecked + trivial + flagged + clear = 2 × (pairs − skipped_pairs)` が常に成り立ちます。分析はパックの有無に関係なく動き（パックなしの状態では findings JSON は `packs: []` / `pack_info: []` ＋ 導出結果）、`--no-derived` で導出の痕跡が全て消えます。列名と件数のみで、セルの値は一切出ません。

所見は集計値と列名のみで、**セルの値は一切出ません**。`findings.packs` は従来どおりパック id の配列（読み手は不変）。トップレベルの `pack_info` が読み込み順に `{id, version, source, sha256}` を並べます（`sha256` は読み込んだバイト列そのもの・組み込みは文字列定数の UTF-8 バイト列のハッシュ・`version` ## 13. audit（v0.7.0、観測のみ）

`audit FILE -c CONFIG [--subject COLUMN] [--findings-json FILE] [--lang]` は、表を **今のまま** 観測します。一般化もせず、除外もせず、拒否もせず、判定もしません。`plan` が実行の見積り、`run` が表の変換だとすれば、`audit` は数えるだけです。報告はすべて整数で、割合は千分率の切り捨て（`1000 * count // n`、`n = 0` は 0）。浮動小数点は一切計算しないため、同じ表はどの環境でもバイト同一の出力になります。設定から使うのは `qi` 列・`k`・`l` と各列の役割（subject の検証用）だけで、**一般化は適用しません**。表の値をそのまま観測します。オプション `--delimiter --in-format --max-rows --max-evals --findings-json --quiet --lang` は `plan` と同じ挙動で、人間向けの報告は stderr に、stdout は空のまま、書き込むファイルは任意の `--findings-json` だけです。終了コード： 0（観測の完了。警告があっても 0）· 1（I/O）· 2（設定/使い方/入力）。拒否の状態はありません。

**既存方針との一致。** 値はエンジンの `_norm`（NFC＋前後空白除去）で比較し、同値類は `measure`/`diagnose` の段階 0 と同じ作り方です。すべての行が参加し、空の QI 値は空文字列という値として振る舞い、`missing_value_policy` は**適用しません**（行を除外するのは変換であって観測ではないため）。したがってこれらは `plan` が段階 0 の `before` として報告するのと同じ数 — `count` = `crowds`、`min_size` = `smallest_crowd`、`unique_rows` = `records_alone`、`rows_below_k` = `records_below_k` — で、同じ名前なら同じ数です（T31 が固定）。

**A — 同値類**（`classes`）: `count`、`min_size`、`unique_rows`（サイズ 1 の同値類に属する行）、`rows_below_k`（サイズが k より小さい同値類に属する行）、`unique_permille` / `below_k_permille`（n に対する千分率・切り捨て）、`size_buckets`（固定バケット `"1" "2" "3" "4" "5-9" "10-49" "50+"` ごとの**行数**。キーは常にすべて存在し、空なら 0。数えるのはクラス数ではなく行数）。

**B — QI 列ごと**（`qi_columns`、正規順序: 列名のソート順）: `distinct`（異なり値数。空セルを除く — inspect の `distinct` は空値も数えますが、audit は数えません。空のセルは値を持たないため）、`unique_rows`（正規化した値が空でなく、その列内で 1 回しか現れない行の数）、`rows_below_k_without`（その列を外した組で同値類を作り直したときの `rows_below_k`。1 列につき O(n)）。QI が 1 列のときは外すと全行で 1 つの同値類になるため、`n < k` なら `n`、それ以外は 0。

**C — 同一対象の繰り返し**（`subject`、`--subject COLUMN` 指定時のみ）: k-匿名性は行について語りますが、人は複数の行にまたがれます。subject 列は、設定にあり役割が `qi`/`sensitive` 以外の列（`id`・`keep`・`drop` は可。典型は id 列）である必要があり、違反は列名だけを述べるメッセージで終了コード 2。観測は `rows_with_subject` / `rows_missing_subject`、`subjects`、`repeated_subjects`（2 行以上に現れる対象）、`rows_in_repeated_subjects`、`max_rows_per_subject`、`rows_per_subject_buckets`（固定バケット `"1" "2" "3-4" "5-9" "10+"` ごとの対象数）、`class_subjects`: 同値類ごとの**異なる対象数** — `min_distinct`、`rows_below_k`（異なる対象数が k 未満の同値類に属する行 = 人の上の k 未満）、`rows_overstated`（サイズは k 以上だが異なる対象数が k 未満の同値類に属する行 = 行の上では安全に見え、人の上では届かない行）。**空の subject 値は 1 行で 1 人の対象**: 空のセル同士は同一人物かどうか判別できないため、空の行はすべて別々の対象（1 行 = 1 人）として、subject 項目のすべてで一貫して扱います（したがって繰り返しにはなりません）。`--subject` がなければ C の項目は現れず、`subject` は `null` です。

**決定性。** 行の並べ替えも列の並べ替えも何も変えません。QI 列はソート順で報告し、集計はすべて順序に依存せず、同じ入力への反復実行はバイト同一です（T36）。

**警告。** 件数として述べる観測の言い換えであって、判定語は使いません。従来の `  - code: …` 書式（英日の 2 通り）で stderr に、findings では `warnings` 要素 `{code, rows}` として現れます: `small_classes`（`rows_below_k > 0`）と `subject_overstated`（`rows_overstated > 0`）。警告は終了コードを変えません（0）。`n` が `--max-rows` を超えるときは、plan と同じく stderr に `rows_over_limit` の注意行を出します（audit は探索しないので、観測は単にすべての行を読みます）。これは audit の警告ではなく findings には入りません。

**findings**（`--findings-json`）: 既存の findings とは別のファイルで、`{"audit": {...}}` の形。`schema: 1` と固定のキー集合 — トップレベルは `schema, rows, k, qi, classes, qi_columns, subject, warnings`。集計と列名のみを運び、**セルの値は一切含みません（subject の値も含む）**（T37）。plan の findings と同じく、原子的かつ無条件に書き換えます。

**範囲の注記。** エントロピーはありません: 対数は出力に浮動小数点を持ち込み、浮動小数点は環境によって末尾の桁が変わることがあります。整数は変わりません。再現性を実測してから、別の版で判断します。`l` は構文解析されますが、audit の項目では使いません（l/t の観測は範囲外）。audit モジュールは audit ハンドラだけが import し、`run`・`plan`・`inspect` は決して import しません（T38 が subprocess の検査を拡張。凍結された `config.py` / `engine.py` は無変更で、その sha256 を T38 が固定します）。実測（依頼書 4.6 節）: 10 万行 × QI 4 列で、subject なしで約 0.4 秒、ありで約 0.6 秒（ラップトップ級 CPU。列を外す B の反復はおよそ O(#QI × n) を追加）。

## 14. 共有の文字表と不可視文字の観測（v0.7.1）

**文字表。** `sieve_crowd/chartable_v1.json` は、Sieve Lens の正本の文字表のバイト完全な複製です（正本は Lens が持ち、Crowd は sha256 `c5ae4757…e605` で固定された複製として扱います。読み込みのたびに再検証します）。標準の変更は上流（Lens 側）で行い、Crowd 側で独自に行いません。`sieve_crowd/chartable.py` はそこから 2 つの固定の置換マップを作り（基本 = 不可視文字の除去・twins・全角 ASCII 範囲・折りたたみ空白、および基本＋ダッシュ）、`fold(text, dashes=False)` を提供します。適用順は: (1) 不可視文字（4 種すべて）を取り除く、(2) twins と全角 ASCII 範囲（U+FF01〜U+FF5E → U+0021〜U+007E）を置き換える、(3) 折りたたみ空白（U+00A0・U+3000）を ASCII の空白にする、(4) `dashes=True` のときだけ折りたたみダッシュ（U+2010〜U+2015・U+2212・U+30FC・U+FF70）を ASCII のハイフンにする。4 段階はコードポイントを共有せず（読み込み時に検証）、ターゲットはすべて印字可能 ASCII なので、fold は冪等で印字可能 ASCII はすべて不変 — 純 ASCII の入力は自分自身に折りたたまれます。**fold の中に Unicode データベースの参照は一切ありません**: 同じ入力はどの Python のビルドでも同じ出力に折りたたまれます（結果を決めるのは表の版であって、実行環境の Unicode データではない）。表は遅延で 1 回だけ読み、欠損・改ざん・形式不良は明確な `ChartableError` — 黙って別の表を使うことはありません。wheel は `package-data` で JSON を同梱します（実ビルドで確認）。`run` はこのモジュールに到達しません（至る所が関数レベル import。T46 の subprocess 検査が chartable と hidden_chars をカバーします）。

**不可視文字の観測（plan のみ）。** パックとは独立に、`plan` はすべての列のすべてのセル — plan が既に読む行なので、plan の `max_rows` が唯一の上限 — を文字表の `invisible` の種類（ゼロ幅 U+200B/200C/200D/2060/FEFF・双方向制御・タグ文字・異体字選択子）で走査します。列ごとに `rows`（1 文字以上を含む行数）・`chars`（総数）・`kinds`（現れた種類のソート済みの名前）を記録します。宣言された役割が `keep`・`qi`・`sensitive` で `rows > 0` の列に 1 件ずつ、列名のソート順で警告を出します。`id` と `drop` の列は要約の件数にのみ入ります（値がそのまま出力に残らないか、捨てられるため）。これは観測であって変更ではありません。セルは 1 つも書き換えず、出力は件数と種類の名前のみ — **セルの値もコードポイントも一切現れません**（T45 は不可視文字入りの番兵を使います）。ファイル先頭の BOM は読み込み側（`utf-8-sig`）で解釈されて数えず、セルの中の U+FEFF は数えます。

警告行は従来の `  - code: …` 書式（英日）です。keep の例: `  - hidden_chars: "memo" (declared keep): 12 row(s) contain invisible characters (zero_width); they stay in the output` / 「memo」（宣言 keep）: 12 行に不可視文字（zero_width）が含まれています。出力にそのまま残ります。 `qi` では観測の意味を述べる文に変わります: `values that look identical form separate groups` / 見た目が同じ値が別のグループに分かれます（`keep`/`sensitive` は「出力にそのまま残ります」）。findings JSON は `warnings` 要素 `{code: "hidden_chars", column, declared_role, rows, chars, kinds}` とトップレベルの `hidden_chars_summary = {columns_checked, columns_flagged}` を加えます — キーの追加のみ（追加のみの契約）。findings が書かれ、走査が実行されたときに付きます。`--no-hidden-chars` は観測全体を省きます（行も要素も要約も出ません）。純 ASCII のセルは `isascii()` の高速経路を通ります。10 万行 × 10 列での費用はリリース報告に実測値があります。

## 15. scan（v0.8.0、1 枚の静的 HTML）

`scan INPUT [-c CONFIG] [--hint-pack FILE]... [--no-builtin-hints] [--no-hidden-chars] [--subject COLUMN] [--k N] [--max-rows N] [--no-derived] [--lang en|ja] [-o PATH|-]` は、読み取り専用のコマンドが既に持っている測定を **1 枚の静的 HTML** に組み立てます — 読み物として: "この表は、いまどう見えているか"。**新しい測定は作りません。** `-c` なしでは役割は仮のもの（列ごとのヒントパック候補のいちばん上 — v0.5.2 の順 = 根拠の強さ → 役割 → ルール id。候補のない列は `未割当（仮に keep）`、`id` の提案は「仮・出力から除く前提」と明示）。`-c` ありでは宣言された役割をそのまま使います（scan = plan + audit を 1 度の読み物に）。仮の役割の経路の内部設定はすべての qi を `exact` で一般化し、どこにも書き出しません。「次の一手」の節の下書きは提案自身の一般化器を使い、未決列は `?` にします。

**ページの構成（上から下へ）。** 見出し（ベース名 — 標準入力なら "(standard input)" / 「（標準入力）」—、行数 × 列数、入力の SHA-256、版、読み込んだパックとその版、k）· 平易な文の要点（3〜5 行）· 列の一覧（役割・いちばん上の候補の根拠・候補ルール id・5 種類の所見の件数のみ — `hidden_chars`、`japanese_era`、`leak`、`mixed_form`、`role_mismatch`。書かれていない種別は 0 件）· グループの大きさ（`audit` の `size_buckets`、整数切り捨ての棒と数値）· 列ごとの観測（`audit` の `qi_columns`）· 導出関係（`--no-derived` で節を省略）· 同一対象の繰り返し（`--subject` は `audit` の C 観測を実行。なければ対象列の候補名を載せた案内）· 次の一手（設定の下書きと `plan`/`run` のコマンド例を `<pre>` で。例のファイル名は入力のベース名と `config.json` — `-c` ありなら設定のベース名。標準入力の例は `input.csv`）· この報告について（先頭は 3 つの注意書き: これは観測であって判定ではない — 数値はいまの役割の置き方での値、1 人が 1 行の表の前提 — 同じ人が複数の行にいるときは `--subject` で観測、k-匿名性は別の情報との照合やグループ内の値からの属性の推測を防がない）。各節は 1〜2 行の「この節の読み方」で始まります。仮の qi 候補が 1 つもなければ、グループ・観測・導出関係の節を省き、案内文に置き換え、終了コードは 0 のまま。このとき `--subject` は使われません（対応づける同値類がないため）。

**文言と数値。** 観測であって判定ではありません: 「安全」「危険」「合格」「不合格」はどこにもなく、ポジティブファースト。割合は千分率の切り捨て（`1000 * count // n`、`n = 0` は 0）を小数 1 桁で表示（整数演算のみ — 浮動小数点は計算されない）。棒の幅は整数パーセントの切り捨て。所見は固定順: code の昇順 → 列名（コードポイント順）→ 既定の順 — 依頼書 §11 への追認事項として承認済み。要点の役割の内訳は各列を一度だけ数えます（`-c` なしは仮の keep を `未割当（仮に keep）` の 1 区分にまとめ、`-c` ありは宣言された役割のみを数える — 二重計上はない）。

**HTML 衛生。** 1 ファイル、UTF-8（BOM なし）、`\n` 改行、`<html lang>` は `--lang` に従属。`<script>`、`on*=` 属性、`src=`/`href=`/`url(`/`@import`/`<link>` は一切なし。CSP meta は `default-src 'none'; style-src 'unsafe-inline'`。インライン CSS のみ、`prefers-color-scheme` によるライト/ダーク、印刷・スマホ幅対応、中性色（色は情報を運ばない — 棒には必ず数値が併記される）。ユーザー由来の文字列（列名・ベース名・パック id と版・ルール id・下書き JSON）は HTML エスケープ — `= ( ) @` を含むので、悪意ある名前は禁じられたトークンを作れない — され、不可視・制御文字は `<U+XXXX>` で表示（文字表の invisible 分類＋ C0（タブと改行を除く）＋ C1＋ DEL）。列名の表示は最大 120 コードポイント（表示のみ — 下書きは全文を保つのでコピーペーストに耐える）。日時・乱数・環境依存の値（パス・ホスト名・ロケール）はなく、ファイル名はベース名のみ。同じ入力はバイト同一。セルの値は一切現れない — ほかの報告と同じ番兵規則がページ全体に適用されます。

**入出力と終了コード。** 出力の既定は `INPUT` の最後の拡張子を `.scan.html` に置き換えたもの（`people.tar.csv` → `people.tar.scan.html`）で、アトミックかつ無条件に上書き — `--force` は存在しない。`-o PATH` は任意のパス、`-o -` は標準出力。出力先が解決後に入力ファイルまたは `-c` のファイルと同じになるとき、および入力が標準入力で `-o` がないときは拒否（終了コード 2、何も書かない）。オプションは plan/audit と同じ意味に従います: `--k` は仮の役割用の k（既定 5。`-c` ありでは plan と同じ規則で設定の k に優先）、`--max-rows`（既定 200,000）は audit と同じ意味 — 観測はすべての行を読み、表が大きいときはページがその旨を記録 — `--no-hidden-chars` は不可視文字の観測を省く（件数は keep/qi/sensitive の列にのみ付き、仮の `id` 列には付かない）、`--hint-pack`/`--no-builtin-hints` は §12 どおり。`--delimiter`/`--in-format` は存在しません（標準入力は CSV、それ以外は拡張子で判定）。終了コード: 0 成功（所見ゼロの表も含む）· 1 I/O · 2 使い方/設定/入力。stderr の完了報告は 1 行（出力先と件数の要約、英日）。ブラウザは開かない。ページを読む側にも書き換えは起きない。`scan` モジュール（`sieve_crowd/scan.py`）は scan ハンドラだけが import し — `run`・`plan`・`inspect`・`audit` は決して import しません（T67 が subprocess 検査を拡張。テスト T67〜T77）。`examples/people.csv` の 4 つの scan の読み（英日 × 設定なし/`-c`）は SHA-256 で固定します（T79 — ページに版とパック情報が載るため、版を上げるたびに実測で張り直します）。設定なしの読み 2 つは `docs/samples/people.scan.en.html` と `docs/samples/people.scan.ja.html` としてコマンドの出力とバイト一致で同梱します（T80）。

| — | `numeric` にはカスタム `bins`（内部境界、両端は開区間） | 法令や実務の階級区分は不均一。`widths` の倍数の規則はそのまま残す |

| — | `missing_value_policy` は `star`（既定）か `suppress` のみ。placeholder は提供しない | 埋めた値は欠損パターンそのものを準識別子にする。除外は数えられる予算の中で誠実に行う |
| — | 第2段階は単調性による枝刈り付きの深さ優先走査で、領域を材料化しない | 最適解は総当たりのオラクルで固定する。領域サイズのリストをメモリに持たない。評価数は参考値 |
| — | `plan` は正確な値だけを報告し、探索を実行しない | 推定は「測定する保証」という姿勢を削る。格子の大きさは設定から正確に決められる |
| — | 形式は拡張子で判定し、`--in-format` / `--out-format` で上書き。Excel は対応しない | 予測できるファイルと曖昧さのない例外処理、外部の読み込みライブラリを入れない |
| — | JSON はレコード配列か明示形。セルは入口で文字列に正規化 | エンジンは形式に依存せず、厳格な拒否が表の曖昧さをなくす |
| — | XML のフィールドは `name` 属性を持つ。DOCTYPE と名前空間は全面拒否 | 列名は任意の文字列（要素名にはできない）であり、プライバシーの道具がエンティティ展開する入力を解釈してはならない |
| — | 欠損はどの形式でも空のセル（`null` → `""`、空要素 → `""`） | 往復が安定し、出力が `null` を作らない |
| — | 形式非依存性をテストされた不変条件にする | 保証が、表を運んだ形式に依存してはならない |
| — | 文字の折りたたみは固定の表（sha256 固定の Lens 複製）であって、Unicode データベースの呼び出しではない | 同じ入力はどの Python でも同じ出力に折りたたまれる。基準は「探す」のでなく「持つ」 |
| — | 不可視文字は書き換えず観測する（plan・件数のみ） | 除去はデータの書き換えになる。意味のある場所（keep/qi/sensitive）に警告するのが誠実な半分 |
